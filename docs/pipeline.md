## Configuration and rerun policy

1. Freeze the revised `experiment_utils.py`, `experiment_protocol.md`, configuration files and script versions before the corrected runs. `experiment_utils.py` is a shared module; do not run it as a standalone stage. All shared/resolved configs use `schema_version: "thesis-run-config-v3"` and `run_id: "left_truncation_v2"`; old schemas are rejected.
2. `1b_select_benchmark_max_length.py` must estimate token lengths using the benchmark **training split only**, under both tokenizers. It must not use validation/test token lengths for the length decision. `8_timing_pilot.py` separately chooses contextual maximum length and contextual learning rates.
3. Explicitly set `tokenizer.truncation_side = "left"` for every contextual training and inference tokenization; the target is last in the concatenated input. Reuse the saved configuration instead of hard-coding `128` or `152` independently across scripts.
4. Stage 11 must first audit all 50 manifest-verified runs for each backbone, record each grid fingerprint, verify C0/C_best prediction post-ID order, and use paired bootstrap intervals—not separate CI overlap. It must write `results/backbone_decision.json`. Stages 12–17 must load the decision file and fail if it is missing, stale, or invalid.
5. The `3_train_e1.svm` file remains outside the main run order as optional/legacy. Do not include it as an Experiment I backbone in the declared decision unless the research design is formally changed.
6. For clean provenance, rerun the pipeline chronologically after the code and configurations are frozen. Re-run preprocessing to verify deterministic reproduction, then assert that stable post IDs and shared fold assignments match the frozen manifest. If they differ, stop and investigate rather than silently comparing mismatched predictions. Archive historical contextual outputs and use `results/runs/left_truncation_v2/`: old prediction/probability files must never satisfy a resume check. Before execution, `audit_pipeline_script_names()` must pass; stage scripts must use `validate_resolved_run_config()`, `make_run_manifest()`, `prepare_run_directory()`, and `assert_current_run_artifact(path, expected_stage=..., expected_script=..., expected_fingerprint=...)`. `make_run_manifest()` requires the registered script and both study documents to exist, and its self-fingerprint, utility/script/document hashes, config and input hashes are checked before resume.
